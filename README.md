# 360GS Prototype v0.3a

360°写真、360°動画、3D Gaussian Splattingを、専門的な設定なしでブラウザ上から扱うためのプロトタイプです。

## 基本方針

利用者の操作は原則として「ファイルを選ぶ → 自動処理 → 見る」です。解析間隔、RANSAC、SfM、特徴点追跡、Bundle Adjustment、COLMAP形式などの技術設定を利用者が行う必要はありません。

自分で選択した写真、動画、3DGSファイルと解析中間データは、現段階ではサーバーへアップロードせず、端末内のブラウザで処理します。

## この版でできること

### 360°写真

- JPEG / PNG / WebPの360°写真を選ぶだけで表示
- 2:1の360°画像らしいかを自動確認
- ブラウザ内で自由に見回す

### 3DGS

- `.ply`、`.compressed.ply`、`.sog` を選ぶだけで表示
- ドラッグで回転、ホイールで拡大縮小
- モデルの大きさに合わせて初期視点を自動調整
- PlayCanvas公式サンプルで動作確認可能

### 360°動画

- Insta360 Studioなどから書き出したMP4等を読み込み
- 縦横比、解像度、長さを自動確認
- 最大12枚の確認用代表画像を自動抽出
- 動画時間に応じて短時間・標準・長時間モードを自動選択
- 動画全体の連続性を適応型に確認
- 360°キーフレームを4方向の透視画像へ変換
- 局所特徴点と対応点を自動探索
- 360°方向ベクトルへ逆投影
- RANSAC + Essential matrixで相対回転と移動方向を推定
- 不安定区間を自動分割
- 3D化候補区間だけを高密度に局所SfM再計算
- 隣接フレームと1枚飛ばしフレームの幾何整合を確認
- 疎な3D点を三角測量
- 観測不足時に高密度特徴点を自動再探索
- 前・右・後・左の観測分布を確認
- 改善した特徴追跡だけを安全化した軽量Bundle Adjustmentへ渡す
- 全体最適化が良好な区間だけ3DGS学習用データセットを自動生成
- 学習画像、COLMAPテキスト形式カメラ姿勢、`init.ply` をZIPとして保存

## v0.3a 3DGS学習用データセット生成

全体最適化で「良好」と判定された区間だけを対象にします。保留区間を無理に3DGSへ渡しません。

### 処理内容

1. 最適化済み区間から最大24キーフレームを自動選択
2. 各360°フレームを前・右・後・左の4方向へ透視投影
3. WebGLを使い、元動画から640 / 768 / 1024 pxの高画質JPEGを自動生成
4. 4方向の仮想カメラへ最適化済みカメラ姿勢を展開
5. COLMAPの`PINHOLE`モデルとして内部パラメータと外部パラメータを出力
6. Bundle Adjustment後の疎3D点を`init.ply`として出力
7. すべてをZIPにまとめ、画面の「学習データZIPを保存」から保存可能

### ZIP構成

```text
360gs_segment_X_colmap.zip
├─ images/
│  ├─ f000_front.jpg
│  ├─ f000_right.jpg
│  ├─ f000_back.jpg
│  ├─ f000_left.jpg
│  └─ ...
├─ sparse/
│  └─ 0/
│     ├─ cameras.txt
│     ├─ images.txt
│     └─ points3D.txt
├─ init.ply
├─ dataset.json
└─ README.txt
```

`cameras.txt` / `images.txt`はCOLMAPテキスト形式です。`points3D.txt`は現段階では空の疎点リストとし、最適化済み疎点群はBrushの初期化に使いやすい`init.ply`として別途格納します。

カメラ移動の絶対距離スケールはまだ未確定のため、データセットの位置・点群も任意スケールです。

## 動画時間への対応

数十秒から約15分程度までを想定し、動画時間に合わせて内部処理量を自動調整します。長時間動画でも全フレームをメモリへ保持しません。

- 連続性解析: 60秒以下 最大約36フレーム、1〜5分 最大約90、5分超 最大約180
- 局所特徴点解析: 60秒以下 最大18キーフレーム、1〜5分 最大28、5分超 最大40
- 相対姿勢解析: 60秒以下 最大30キーフレーム、1〜5分 最大56、5分超 最大90
- 局所SfM: 1候補区間 最大24フレーム、1動画 最大72フレーム
- 高密度追跡: 端末性能と対象フレーム数に応じて176 / 256 / 320 pxを自動選択
- 学習データ出力: 良好区間ごとに最大24キーフレーム、4方向で最大96学習画像

## 相対カメラ姿勢推定

透視画像で検出した対応点を360°カメラ中心から見た3次元単位方向ベクトルへ戻し、RANSACと8点法からEssential matrixを推定します。外れ対応を除いた後、相対回転と移動方向を推定します。

画面の「幾何学的内点率」はエピポーラ幾何に整合した対応点の割合、「視差角」は推定回転を除いた後に残る方向差の中央値です。

実動画で100°を超える極端な視差が確認されたため、局所SfMでは35°を超える視差を姿勢破綻の可能性が高い異常候補として扱います。この閾値は実データで今後校正します。

## 自動区間分割と局所SfM

隣接キーフレームを無理に1本の軌跡としてつながず、姿勢推定が弱い区間、内点率が低い区間、視差不足区間を境界候補として扱います。安定した候補区間だけフレーム密度を上げて再計算し、疎な3D点群と仮のカメラ軌跡を構成します。

## 高密度特徴点追跡

Bundle Adjustment前に、局所SfMで残った候補区間だけを端末性能に合わせて再解析します。高信頼・中信頼の観測を残し、隣接、1枚飛ばし、必要時は2枚飛ばしまで使って複数視点トラックを構成します。トラック数・観測数・方向分布が不足する場合は最大2回まで自動再探索します。

現在の暫定判定は以下です。

- 良好: 50トラック以上、180観測以上、かつ方向分布が許容範囲
- 試行可能: 25トラック以上、100観測以上
- 追加探索が必要: 12トラック以上だが上記に未到達
- 保留: 12トラック未満

これらは最終的な科学的閾値ではなく、実動画と最終3DGS生成成功率を照合して今後校正します。

## 安定化した軽量Bundle Adjustment

ブラウザ上の小規模候補区間を対象に、360°方向ベクトルの観測誤差を使ってカメラ姿勢と疎3D点を調整します。Huber型ロバスト損失、MADベースの外れ観測整理、step scaleの比較、反復ごとの全体評価、安全ロールバックを使用します。

全体指標が悪化する更新は採用しません。最終結果が初期状態より悪い場合も最適化前へ戻します。

これはCeres Solver等の大規模Schur complementベースBundle Adjustmentそのものではなく、ブラウザだけで動作する小規模候補区間向けの軽量実装です。

## 現在のプライバシー

選択した360°写真、360°動画、3DGSファイル、代表画像、透視画像、特徴点、相対姿勢、区間分割、局所SfM、高密度特徴追跡、Bundle Adjustment、3DGS学習画像は端末内で処理します。ZIPを保存するまで外部サーバーへ送信しません。

## この版ではまだできないこと

- メートル単位の絶対移動距離を確定する
- Ceres等と同等の大規模疎Bundle Adjustment
- 再訪位置や長距離対応を使ったループ閉合
- 生成したCOLMAPデータを360GS内でBrushへ直接渡して3DGS学習を開始する
- 360°動画から3DGSを最後まで自動生成する
- Cloudflare R2へ保存する
- メール認証による限定共有
- 作成した3DGSのオンライン永続保存

## 使い方

1. GitHub Pagesの360GSを開く
2. 「360°動画から3Dを作る」を選ぶ
3. Insta360 Studioなどから書き出した2:1のMP4を選ぶ
4. 以降は自動処理
5. 全体最適化が良好な区間では「3DGS学習データの準備」が自動で始まる
6. 「学習データZIPを保存」を押す
