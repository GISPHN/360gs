# 360GS Prototype v0.2f

360°写真、360°動画、3D Gaussian Splattingを、専門的な設定なしでブラウザ上から扱うためのプロトタイプです。

## この版でできること

### 360°写真

- JPEG / PNG / WebPの360°写真を選ぶだけで表示
- 2:1の360°画像らしいかを自動確認
- ブラウザ内で自由に見回す

### 3DGS

- `.ply`、`.compressed.ply`、`.sog` を選ぶだけで表示
- ドラッグで回転、ホイールで拡大縮小
- モデルの大きさに合わせて初期視点を自動調整
- PlayCanvas公式サンプルで動作確認可能

### 360°動画

- Insta360 Studioなどから書き出したMP4等を選択またはドラッグで読み込む
- 縦横比、解像度、長さを自動確認
- 最大12枚の確認用代表画像を自動抽出
- 動画時間に応じて短時間・標準・長時間モードを自動選択
- 動画全体の連続性を適応型に確認
- 360°キーフレームを前・右・後・左の4方向の透視画像へ変換
- 局所特徴点を抽出し、隣接キーフレーム間の対応点を自動探索
- 対応点を360°カメラ座標の3次元単位方向ベクトルへ戻す
- RANSAC + Essential matrixで相対回転と移動方向を推定
- 幾何学的内点率、視差角、姿勢推定の成立状況を表示
- 不安定な区間を境界候補として自動分割
- 安定した区間を「良好候補 / 3D化候補 / 保留」に分類
- 3D化候補区間だけフレーム密度を上げて局所SfMを再計算
- 隣接フレームに加えて1枚飛ばしの幾何整合を確認
- 成立した対応から疎な3D点を三角測量
- 候補区間ごとのカメラ軌跡と疎点群を上面図で表示

## 動画時間が異なる場合

利用者が解析間隔を設定する必要はありません。数十秒から約15分程度までを想定し、動画時間に合わせて内部処理量を自動調整します。

### 連続性解析

- 60秒以下: 最大約36フレーム
- 1〜5分: 最大約90フレーム
- 5分超: 最大約180フレーム

### 局所特徴点解析

- 60秒以下: 最大18キーフレーム
- 1〜5分: 最大28キーフレーム
- 5分超: 最大40キーフレーム

### 相対姿勢解析

- 60秒以下: 最大30キーフレーム
- 1〜5分: 最大56キーフレーム
- 5分超: 最大90キーフレーム

### v0.2f 局所SfM再計算

自動分割後に残った3D化候補区間だけを対象にします。全動画へ高密度処理をかけません。

- 1候補区間あたり最大24フレーム
- 1動画あたり最大72フレーム
- 区間が短いほど高密度、長いほど間引いて自動配置
- 隣接フレームと1枚飛ばしフレームの両方で幾何整合を確認
- 疎な3D点は最大約1,600点まで保持

長時間動画でも全フレームをメモリへ保持しません。

## 相対カメラ姿勢推定

局所特徴点は4枚の透視画像上で検出しますが、幾何計算では透視画像の座標をそのまま使いません。既知の画角と各透視方向から、各対応点を360°カメラ中心から見た3次元単位方向ベクトルへ変換します。

対応点から中央投影カメラのエピポーラ拘束を構成し、8点法をRANSAC内で反復します。外れ対応を除いた後にEssential matrixを再推定し、相対回転と移動方向へ分解します。

画面の「幾何学的内点率」は、推定したエピポーラ幾何に整合した対応点の割合です。「視差角」は、推定回転を除いた後に残る方向差の中央値です。

### 視差角の異常値対策

実動画で100°を超えるような極端な視差角が確認されたため、v0.2fでは局所SfM再計算時に35°を超える視差を姿勢破綻の可能性が高い異常候補として扱います。これは現時点の安全側の初期閾値であり、今後の実データで校正します。

## 自動区間分割

隣接キーフレームごとの相対姿勢結果を無理に1本の軌跡として連結せず、姿勢推定が弱い、内点率が低い、視差が不足する区間を分割境界候補として扱います。

現在の初期基準は次のとおりです。

- 分割境界候補: 姿勢推定が弱い、内点率25%未満、または視差角0.16°未満
- 3D化候補: 2姿勢区間以上、約1.2秒以上、内点率中央値30%以上、視差角中央値0.16°以上
- 良好候補: 3姿勢区間以上、内点率中央値45%以上、視差角中央値0.45°以上、かつ良好判定が区間内の50%以上

これらはプロトタイプの初期閾値です。複数の実動画と最終的な3DGS生成成功率を照合して校正します。

## v0.2fの局所SfM再計算

自動分割で3D化候補になった区間について、元の粗い姿勢推定とは別にフレーム密度を上げて再計算します。

1. 候補区間内へキーフレームを追加
2. 各フレームから360°対応点を再取得
3. 隣接フレーム間のRANSAC / Essential matrixを再計算
4. 1枚飛ばしのフレーム間でも姿勢が成立するか確認
5. 成立した相対姿勢を任意スケールで連結
6. 幾何学的内点を2視点から三角測量
7. 疎な3D点群とカメラ軌跡の上面図を表示

局所SfMの評価では、姿勢成立率、内点率中央値、視差角中央値、1枚飛ばし整合率、疎3D点数を使用します。

重要: v0.2fはBundle Adjustmentをまだ実行していません。各相対姿勢を独立に求めて連結し、三角測量による局所幾何の成立性を確認する段階です。次段階で複数フレームのカメラ姿勢と3D点を同時最適化するBundle Adjustmentを追加します。

## 絶対スケールについて

相対姿勢で求まる移動量は方向のみです。単眼映像の相対姿勢だけではメートル単位の絶対距離スケールは決まりません。v0.2fのカメラ軌跡と疎点群も任意スケールです。

## プライバシー

自分で選択した360°写真、360°動画、3DGSファイルはサーバーへアップロードせず、端末内のブラウザだけで処理します。代表画像、透視画像、局所特徴点、相対姿勢、自動区間分割、局所SfMの中間データも現段階では外部へ送信しません。

## この版ではまだできないこと

- メートル単位のカメラ移動距離を確定する
- Bundle Adjustmentで複数カメラ姿勢と3D点を同時最適化する
- 分割した複数区間の再訪位置を検出して自動接続する
- 360°動画から3DGSを最後まで自動生成する
- Cloudflare R2へ保存する
- メール認証で限定共有する
- 作成した3DGSをオンライン上で永続保存する

## 使い方

1. GitHub Pagesの360GSを開く
2. 「360°写真を見る」「3DGSファイルを見る」「360°動画から3Dを作る」のいずれかを選ぶ
3. ファイルを選ぶ
4. 以降は自動処理

360°動画では、Insta360 Studioから書き出した2:1のMP4を推奨します。解析間隔、動画時間、RANSAC、分割閾値、局所SfM設定を利用者が行う必要はありません。

## 技術構成

- HTML / CSS / JavaScript
- Photo Sphere Viewer 5.15.0
- Three.js 0.179.1
- PlayCanvas Engine 2.21.4
- HTMLVideoElement / Canvasによるローカル動画解析
- 適応型equirectangular連続性チェック
- equirectangularから4方向の透視画像への変換
- 軽量コーナー検出、正規化パッチ記述子、相互最近傍マッチング
- 360°bearing vectorへの逆投影
- RANSAC + 8点法 + Essential matrix制約
- Cheiralityによる相対姿勢候補選択
- 相対姿勢・内点率・視差角を用いた自動区間分割
- 高密度化した候補区間の局所SfM再推定
- 隣接 / 1枚飛ばし姿勢整合
- 2視点ray triangulationによる疎3D点生成

利用者が理解する必要のない専門用語や設定項目は通常画面から隠します。基本操作は今後も「ファイルを選ぶ → 自動処理 → 見る → 必要なら共有する」とします。
