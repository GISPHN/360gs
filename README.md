# 360GS Prototype v0.2i

360°写真、360°動画、3D Gaussian Splattingを、専門的な設定なしでブラウザ上から扱うためのプロトタイプです。

## 基本方針

利用者の操作は原則として「ファイルを選ぶ → 自動処理 → 見る」です。解析間隔、RANSAC、SfM、特徴点追跡、Bundle Adjustmentなどの技術設定を利用者が行う必要はありません。

自分で選択した写真、動画、3DGSファイルと解析中間データは、現段階ではサーバーへアップロードせず、端末内のブラウザで処理します。

## この版でできること

### 360°写真

- JPEG / PNG / WebPの360°写真を選ぶだけで表示
- 2:1の360°画像らしいかを自動確認
- ブラウザ内で自由に見回す

### 3DGS

- `.ply`、`.compressed.ply`、`.sog` を選ぶだけで表示
- ドラッグで回転、ホイールで拡大縮小
- モデルの大きさに合わせて初期視点を自動調整
- PlayCanvas公式サンプルで動作確認可能

### 360°動画

- Insta360 Studioなどから書き出したMP4等を読み込み
- 縦横比、解像度、長さを自動確認
- 最大12枚の確認用代表画像を自動抽出
- 動画時間に応じて短時間・標準・長時間モードを自動選択
- 動画全体の連続性を適応型に確認
- 360°キーフレームを4方向の透視画像へ変換
- 局所特徴点と対応点を自動探索
- 360°方向ベクトルへ逆投影
- RANSAC + Essential matrixで相対回転と移動方向を推定
- 不安定区間を自動分割
- 3D化候補区間だけを高密度に局所SfM再計算
- 隣接フレームと1枚飛ばしフレームの幾何整合を確認
- 疎な3D点を三角測量
- 3フレーム以上の複数視点特徴トラックを構成
- 観測不足時に高密度特徴点を自動再探索
- 前・右・後・左の観測分布を確認
- 改善した特徴追跡だけを安全化した軽量Bundle Adjustmentへ渡す

## 動画時間への対応

数十秒から約15分程度までを想定し、動画時間に合わせて内部処理量を自動調整します。長時間動画でも全フレームをメモリへ保持しません。

- 連続性解析: 60秒以下 最大約36フレーム、1〜5分 最大約90、5分超 最大約180
- 局所特徴点解析: 60秒以下 最大18キーフレーム、1〜5分 最大28、5分超 最大40
- 相対姿勢解析: 60秒以下 最大30キーフレーム、1〜5分 最大56、5分超 最大90
- 局所SfM: 1候補区間 最大24フレーム、1動画 最大72フレーム
- v0.2i高密度追跡: 局所SfMで残った候補区間だけを対象にし、端末性能と対象フレーム数に応じて176 / 256 / 320 pxの透視画像を自動選択

## 相対カメラ姿勢推定

透視画像で検出した対応点を360°カメラ中心から見た3次元単位方向ベクトルへ戻し、RANSACと8点法からEssential matrixを推定します。外れ対応を除いた後、相対回転と移動方向を推定します。

画面の「幾何学的内点率」はエピポーラ幾何に整合した対応点の割合、「視差角」は推定回転を除いた後に残る方向差の中央値です。

実動画で100°を超える極端な視差が確認されたため、局所SfMでは35°を超える視差を姿勢破綻の可能性が高い異常候補として扱います。この閾値は実データで今後校正します。

## 自動区間分割と局所SfM

隣接キーフレームを無理に1本の軌跡としてつながず、姿勢推定が弱い区間、内点率が低い区間、視差不足区間を境界候補として扱います。安定した候補区間だけフレーム密度を上げて再計算し、疎な3D点群と仮のカメラ軌跡を構成します。

絶対スケールは未確定であり、表示する軌跡や点群はメートル単位の実距離ではありません。

## v0.2i 高密度特徴点追跡

v0.2hの実動画検証では、安全化したBundle Adjustment自体は悪化を防げた一方、事前除外後に複数視点トラック11本、観測40点まで減る例が確認されました。このためv0.2iでは、Bundle Adjustmentをさらに強くするのではなく、その前段で観測を増やす処理を追加しました。

### 実装内容

1. 局所SfMで残った候補区間のみ再解析
2. 端末性能と対象フレーム数から透視画像解像度を自動選択
3. 4方向それぞれで高密度コーナー候補を抽出
4. 局所コントラストとコーナー強度から特徴の基礎信頼度を算出
5. 相互最近傍とdescriptor ratioから対応信頼度を算出
6. 隣接、1枚飛ばし、必要時は2枚飛ばしまで使って複数視点トラックを構成
7. 高信頼、中信頼、低信頼に分け、明確に弱いトラックのみ除外
8. 前・右・後・左の観測分布を確認
9. トラック数、観測数、方向分布が不足する場合は最大2回まで自動再探索
10. 最も良かった追跡結果だけを次のBundle Adjustmentへ渡す

### 現在の暫定判定

- 良好: 50トラック以上、180観測以上、かつ方向分布が許容範囲
- 試行可能: 25トラック以上、100観測以上
- 追加探索が必要: 12トラック以上だが上記に未到達
- 保留: 12トラック未満

これらは最終的な科学的閾値ではなく、今後複数の実動画と3DGS生成成功率を照合して校正するための初期基準です。

高解像度で検出した特徴点の座標は、後段の既存360°カメラモデルと整合するよう176 px基準の座標系へ正規化してから渡します。これにより、特徴記述は高密度化しつつ、既存のbearing計算との互換性を維持します。

## v0.2h 安定化した軽量Bundle Adjustment

v0.2gの実動画検証で、局所ブロックの誤差は低下しても、区間全体の角度誤差中央値やRMSが悪化する場合が確認されました。v0.2hでは、悪化した最適化結果を採用しないよう安全機構を追加しました。v0.2iでもこの安全機構をそのまま維持します。

### 安全機構

1. 特徴対応を厳しく選択
2. 3フレーム以上かつ十分な時間幅を持つトラックのみ使用
3. 初期姿勢で各観測の角度誤差を計算
4. median absolute deviationを用いて明らかな外れ観測を事前整理
5. 外れ整理後に各3D点を再三角測量
6. Huber型ロバスト損失で残る外れ値の影響を抑制
7. 3D点とカメラ姿勢の更新幅を小さく制限
8. 各更新で複数のstep scaleを試し、局所コストが低下する更新だけを採用
9. 各反復終了後に区間全体のロバストコスト、角度誤差中央値、RMSを再評価
10. 全体指標が悪化した反復は直前の状態へ自動ロールバック
11. 最終結果が初期状態より悪い場合も最適化前へ戻す
12. 最適化候補・良好判定の基準を厳格化

最適化で改善しない場合は、結果を良く見せるために無理に更新せず「保留」とします。

### 実装の位置づけ

これはCeres Solver等の大規模Schur complementベースBundle Adjustmentそのものではありません。ブラウザだけで動作する小規模候補区間向けの、ロバストなブロック交互Gauss-Newton型最適化です。

## 現在のプライバシー

選択した360°写真、360°動画、3DGSファイル、代表画像、透視画像、特徴点、相対姿勢、区間分割、局所SfM、高密度特徴追跡、Bundle Adjustmentの中間データは、現段階では端末内だけで処理します。

## この版ではまだできないこと

- メートル単位の絶対移動距離を確定する
- Ceres等と同等の大規模疎Bundle Adjustment
- 再訪位置や長距離対応を使ったループ閉合
- 360°動画から3DGSを最後まで自動生成する
- Cloudflare R2へ保存する
- メール認証による限定共有
- 作成した3DGSのオンライン永続保存

## 使い方

1. GitHub Pagesの360GSを開く
2. 「360°写真を見る」「3DGSファイルを見る」「360°動画から3Dを作る」のいずれかを選ぶ
3. ファイルを選ぶ
4. 以降は自動処理

360°動画はInsta360 Studioから書き出した2:1のMP4を推奨します。
